# Moving a consumer to CNS 2.0.0

For the eight circuit repositories (ghost_tools, SWIZZLE, ASSAY, WARDEN, DRAFTER, JUDGE, BURNISH, WATCHER_MCU)
and any other repository that pins CNS. What each one imports was measured with `cns_composition.consumers.scan`
on the checkouts the manifest pins (2026-10-22); the compatibility column says what 2.0.0 does to that.

|---|---|---|---|
| ghost_tools | `cns.gate` (module) | unchanged | move the pin |
| SWIZZLE | `cns.gate` (module) | unchanged | move the pin |
| ASSAY | `cns.assay`, `cns.gate` (modules) | unchanged | move the pin |
| DRAFTER | `cns.defect.Defect`, `cns.seat.FileEdit` | unchanged | move the pin |

Nothing any of the eight imports is removed, renamed or retyped. `cns_composition.consumers.missing()` is empty
against 2.0.0 for every registered repository, and `tests/public_shape.json` records every field that was added.

## The pin

Every repository pins the tag, spelled the one way pip can resolve together:

```
cns @ git+https://github.com/wking53214/CNS.git@v2.0.0
```

Move it in `pyproject.toml` (and any requirements file or workflow that repeats it) in one commit per repository.
`cns_versions --spelling tag` in the stack workflow fails a pin spelled as a commit. Until the tag exists the
pin stays `@v1.9.0`; the floor stays 1.9.0, so a repository on 1.9.0 is not failed by `cns_versions` while the
others move.

## Breaking, if the owner accepts it: `cns.stack` pins are full commits

`StackPin.commit` must be exactly 40 lowercase hex characters and `StackPin.pins()` no longer matches a prefix.
No circuit repository imports `cns.stack` (Warden reads the manifest JSON itself and has required a full commit
since 0.13.7), so no consumer code changes. A hand-written manifest with a short pin is refused by CNS as it is
already refused by Warden.

## If the owner renames the distribution

Not done in this release. If `cns-contracts` is chosen, the dependency line becomes
`cns-contracts @ git+https://github.com/wking53214/CNS.git@v2.0.0` in the same commit that moves the pin, and
`import cns` stays. A repository that keeps `cns @ ...@v1.9.0` keeps working.

## What the re-pin session will touch in each repository

- the CNS pin line (all eight)
- WARDEN: `Evidence(..., finisher_ran=...)`; its tests that build `Evidence` by keyword need nothing
- JUDGE: optional use of `finisher_ran`; its docstring's "known limit" paragraph can then be shortened
- WATCHER_MCU: optional use of `gaps()` and `dirty_parts()`; its README's "what is not proven" can cite them
- every README or STACK.md that states the CNS version or the tag
